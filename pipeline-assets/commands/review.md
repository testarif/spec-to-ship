# Review the generated change

Use `code-review-and-quality`. Review the generated files and test output against the specification across five dimensions: correctness, readability, architecture, security, and performance. Report only actionable findings, with severity, file and line, impact, and a concrete recommendation. Distinguish confirmed defects from suggestions. Do not modify files during review.

Write `REVIEW.md` with a section for each dimension and a summary of finding count and overall assessment. A clean review must say that no findings were identified rather than inventing issues.
