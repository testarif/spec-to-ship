# Define the specification

Use the `spec-driven-development` workflow. Turn the user's idea into a concise, testable specification before implementation.

Capture the objective, target users, core features with acceptance criteria, technology constraints, project structure, test strategy, and explicit always/never boundaries. Break independent capabilities into modules and state dependency/build order. Do not invent requirements that are not supported by the idea; make reasonable assumptions explicit.

Save the complete specification as `SPEC.md`. This pipeline is autonomous: do not ask questions or wait for approval. Continue using the available information and record unresolved assumptions or constraints in the spec.
