# Definition of Done

Use this as the release-independent quality floor; task acceptance criteria are additional, not a substitute.

- Acceptance criteria are met and behavior is verified at runtime where practical.
- New behavior has meaningful tests; relevant existing tests pass.
- Boundary and error paths are considered.
- The implementation follows the existing project structure and avoids unrelated changes, dead code, and debug output.
- Interfaces, configuration, and compatibility impacts are accounted for.
- User-visible behavior and important operational assumptions are documented.
- Security and accessibility implications are reviewed where relevant.
- Required verification results and remaining risks are reported honestly.
